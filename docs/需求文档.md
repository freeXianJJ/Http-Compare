# HTTP 接口对比测试工具 - 需求文档

## 项目背景

在重构老项目过程中，需要确保新服务与旧服务的所有API接口保持完全一致的行为。为了验证接口的兼容性，需要一个专门的工具来对比新旧服务的接口响应结果。

## 项目目标

开发一个HTTP请求客户端工具，能够同时向新旧两个服务发送相同的请求，并对比响应结果的差异，帮助开发人员快速定位接口不兼容的问题。

## 功能需求

### 1. 接口管理

#### 1.1 Swagger导入
- **功能描述**：支持从swagger.json文件导入所有接口定义
- **详细需求**：
  - 解析swagger.json文件格式
  - 自动提取接口路径、方法（GET/POST/PUT/DELETE等）
  - 自动识别接口参数类型（query、path、body、formData等）
  - 自动提取接口的请求和响应schema定义
  - 支持Swagger 2.0和OpenAPI 3.0规范

#### 1.2 手动添加接口
- **功能描述**：支持用户手动添加和编辑接口
- **详细需求**：
  - 可手动输入接口URL、HTTP方法
  - 可配置请求参数
  - 可保存和管理自定义接口
  - 支持接口分组/分类管理

### 2. 参数配置

#### 2.1 参数类型支持
- **Path参数**：URL路径中的动态参数（如 /user/{id}）
- **Query参数**：URL查询字符串参数（如 ?name=value）
- **JSON Body**：application/json格式的请求体
- **Form Data**：application/x-www-form-urlencoded格式
- **Multipart Form**：multipart/form-data格式（支持文件上传）
- **Headers**：自定义HTTP请求头

#### 2.2 参数配置界面
- 提供友好的参数编辑界面
- 支持参数的增删改查
- 支持参数类型切换
- 参数值支持变量引用

### 3. 全局变量管理

#### 3.1 Token管理
- **功能描述**：支持为新旧服务分别设置不同的Token
- **详细需求**：
  - **旧服务Token配置**：独立配置旧服务的Token值
  - **新服务Token配置**：独立配置新服务的Token值
  - 自动在请求头中添加Token（如 Authorization: Bearer {token}）
  - 支持Token格式自定义（Bearer、Basic、自定义Header名称等）
  - 两个服务的Token完全独立管理，互不影响

#### 3.2 其他全局变量
- 支持自定义全局变量（如baseUrl、userId等）
- 变量可在接口参数中引用（如 {{variableName}}）
- 支持环境变量管理（开发/测试/生产等环境）

### 4. 双端请求发送

#### 4.1 服务配置
- **功能描述**：配置新旧两个服务的地址
- **详细需求**：
  - 旧服务配置：Host + Port
  - 新服务配置：Host + Port
  - 支持协议选择（HTTP/HTTPS）
  - 支持快速切换服务地址

#### 4.2 请求发送
- **功能描述**：同时向新旧服务发送相同的HTTP请求
- **详细需求**：
  - 使用相同的请求参数
  - 使用相同的请求头（除了可能不同的Token）
  - 并发发送两个请求，提高测试效率
  - 记录请求耗时
  - 支持超时配置
  - 支持重试机制

### 5. 响应对比

#### 5.1 响应数据对比
- **功能描述**：对比新旧服务的响应结果，高亮显示差异
- **详细需求**：
  - 对比HTTP状态码
  - 对比响应头（可选）
  - 对比响应体内容
  - 支持JSON格式的深度对比
  - **严格类型对比**：字符串"123"与数字123视为不同
  - **数组对比**：数组元素顺序不同不算差异，只对比元素内容
  - 支持文本格式的逐行对比
  - **不忽略任何字段**：所有字段都参与对比

#### 5.2 差异可视化
- **功能描述**：简单明了地使用颜色展示响应差异
- **详细需求**：
  - **绿色背景**：完全一致的字段/值
  - **红色背景**：存在差异的字段/值
  - **黄色背景**：仅在一侧存在的字段
  - 使用左右并排视图展示（旧服务 | 新服务）
  - 精确高亮到具体的差异字段或值
  - 差异信息一目了然，无需多次点击

### 6. 测试报告

#### 6.1 测试历史
- 保存每次测试的请求和响应
- 记录测试时间和结果
- 支持历史记录查询

#### 6.2 批量测试
- 支持一键测试多个接口
- 生成批量测试报告
- 统计通过率和失败率
- 导出测试结果

### 7. 用户界面

#### 7.1 界面布局
- 左侧：接口列表和分组
- 中间：请求配置区域（参数、Headers等）
- 右侧：响应对比区域（旧服务 vs 新服务）
- 顶部：工具栏（导入、配置、批量测试等）

#### 7.2 交互设计
- 简洁直观的操作流程
- 快捷键支持
- 响应式设计
- 支持暗色/亮色主题切换

## 技术需求

### 技术栈建议
- **应用类型**：纯前端Web应用（单页应用SPA）
- **前端框架**：React / Vue
- **UI组件库**：Ant Design / Element Plus
- **HTTP客户端**：Axios / Fetch API
- **差异对比库**：deep-diff / fast-json-patch（支持数组无序对比）
- **代码编辑器**：Monaco Editor / CodeMirror（用于JSON编辑和高亮）
- **数据存储**：LocalStorage / IndexedDB（浏览器本地存储）
- **部署方式**：静态文件部署，支持Nginx直接托管，无需后端服务
- **内网适配**：无外部依赖，CDN资源本地化

### 性能要求
- 接口导入速度：支持导入1000+接口，耗时<3秒
- 请求响应：单次请求超时配置，默认30秒
- 界面响应：操作响应时间<200ms
- 内存占用：合理的内存管理，避免内存泄漏

### 兼容性要求
- **浏览器支持**：Chrome 90+、Firefox 88+、Edge 90+
- **内网环境**：所有资源本地化，无需外网访问
- **部署简单**：静态文件，可一键部署到任何Web服务器

## 非功能需求

### 安全性
- Token等敏感信息加密存储
- 支持数据导出时脱敏处理
- 不向第三方服务发送任何数据

### 可用性
- 友好的错误提示
- 完善的操作指引

### 可扩展性
- 插件化架构，支持功能扩展
- 支持自定义对比规则
- 支持自定义请求拦截器

## 实施计划

### 第一阶段（MVP）
1. **单接口测试功能**（核心）
   - 手动配置单个接口（URL、Method、参数）
   - 配置新旧服务地址（Host + Port）
   - 配置新旧服务的独立Token
   - 发送双端请求
   - 响应结果对比（严格类型对比、数组无序对比）
   - 差异可视化展示（简单明了的颜色标识）
2. **架构设计**
   - 接口数据结构设计，为批量测试预留扩展性
   - 请求发送模块设计，支持未来并发批量请求
   - 结果存储设计，支持历史记录功能扩展

### 第二阶段
1. **接口管理增强**
   - Swagger导入功能
   - 接口列表和分组管理
   - 接口保存和快速切换
2. **批量测试功能**
   - 一键测试多个接口
   - 批量测试进度展示
   - 批量测试报告（通过率统计）

### 第三阶段
1. **高级功能**
   - 测试历史记录查询
   - 环境变量管理（多环境切换）
   - 测试结果导出
2. **性能和体验优化**
   - 大数据量响应的优化展示
   - 快捷键支持
   - 用户体验细节优化

## 成功标准

### MVP阶段成功标准
1. **部署简单**：5分钟内完成内网部署，无需配置数据库或后端服务
2. **对比准确**：严格类型对比，数组无序对比正确，差异检测准确率100%
3. **结果清晰**：开发人员3秒内能识别响应是否一致，5秒内定位具体差异字段
4. **性能稳定**：单次请求响应时间<100ms（不含接口调用时间），界面流畅无卡顿
5. **架构可扩展**：代码结构清晰，为批量测试预留接口，二期开发改动量<20%

### 最终成功标准
1. 能够成功导入swagger.json并识别所有接口
2. 批量测试100+接口，5分钟内完成
3. 帮助团队将接口验证效率提升80%以上
4. 工具在内网环境稳定运行，零故障

## 附录

### Swagger.json 示例结构
```json
{
  "swagger": "2.0",
  "info": {
    "title": "API",
    "version": "1.0.0"
  },
  "paths": {
    "/user/{id}": {
      "get": {
        "parameters": [
          {
            "name": "id",
            "in": "path",
            "required": true,
            "type": "string"
          }
        ],
        "responses": {
          "200": {
            "description": "Success"
          }
        }
      }
    }
  }
}
```
